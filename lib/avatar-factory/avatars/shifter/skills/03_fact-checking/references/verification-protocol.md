# Reference: Verification Protocol

## Step-by-Step Protocol for Verifying Different Claim Types

This document defines the precise steps for verifying each category of claim found in a Shifter draft.

---

### Protocol A: Direct Quotations

**Steps**:
1. Locate the original source document or recording
2. Find the exact passage containing the quoted words
3. Compare character-by-character with the draft quotation
4. Check that the quote is not taken out of context (read 2 paragraphs before and after)
5. Verify attribution (person said it, person exists, title correct)
6. Note any omissions in the draft with `[...]` or paraphrase indicator

**Pass criteria**: Verbatim match, correct attribution, fair context

**Fail criteria**: Any word changed without brackets, attribution wrong, context distorted

---

### Protocol B: Statistics and Data Points

**Steps**:
1. Identify the primary source of the statistic
2. Locate the exact figure in the source
3. Check the date of the data (when was it collected/published?)
4. Check the methodology (sample size, scope, definitions)
5. Verify arithmetic (if draft performs calculations, re-calculate independently)
6. Check for updates (has newer data been released since the source?)

**Pass criteria**: Number matches, date and methodology documented, calculations correct

**Fail criteria**: Number off by >1%, date unclear, methodology misrepresented, calculation error

---

### Protocol C: Named Individuals and Titles

**Steps**:
1. Confirm the person exists (check official biography, LinkedIn, or institutional page)
2. Confirm current title and role (not outdated title)
3. Confirm the person made the statement attributed to them (if applicable)
4. Check spelling of name (accent marks, order, special characters)

**Pass criteria**: All four confirmations successful

**Fail criteria**: Any mismatch; outdated titles are common failures

---

### Protocol D: Chronology and Events

**Steps**:
1. Verify the date of the event
2. Verify the sequence (what happened before and after)
3. Verify the location
4. Verify the actors involved
5. Check for conflicting accounts of the same event

**Pass criteria**: All elements confirmed; conflicts documented if they exist

**Fail criteria**: Wrong date, wrong sequence, missing key actors

---

### Protocol E: Legal and Regulatory Claims

**Steps**:
1. Locate the actual law, regulation, or court ruling
2. Read the relevant section (do not rely on secondary summaries)
3. Check effective date and jurisdiction
4. Check for amendments or pending changes
5. Consult legal database or expert if interpretation is ambiguous

**Pass criteria**: Text supports claim; no conflicting amendments; jurisdiction correct

**Fail criteria**: Outdated law cited, jurisdiction wrong, interpretation unsupported by text

---

### Protocol F: Economic and Market Claims

**Steps**:
1. Verify the market data (exchange rates, stock prices, commodity prices)
2. Check the date and time of the data (markets change minute-to-minute)
3. Verify the trend direction (increase vs. decrease)
4. Check the causal claim (does the source support the attributed cause?)
5. Look for alternative explanations in reputable analysis

**Pass criteria**: Data accurate, trend correct, causation supported or flagged as interpretation

**Fail criteria**: Stale data, reversed trend, unsupported causal claim presented as fact

---

### Universal Verification Rules

1. **Primary source first**: Always attempt to verify against the original document before accepting secondary coverage.
2. **Context matters**: A true statement in isolation can become false if context is removed.
3. **Recency check**: Data more than 6 months old must be flagged as potentially outdated.
4. **Methodology transparency**: If the source's methodology is opaque, the claim receives [VERIFIED WITH CAVEAT].
5. **No trust by default**: Even Tier 1 sources are spot-checked at least once per draft.
